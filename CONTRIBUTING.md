**Welcome to CONTRIBUTING.md**

Thank you for taking the time to read this before contributing. Please
make sure to review the guidelines and requirements below.

# Rules & Requirements

> Failure to follow these rules will result in your Pull Request being
> automatically closed/rejected.

## DRY (Don't Repeat Yourself)

**We live and breathe by the DRY principle here.**

### No Code Duplication

If you find yourself copying and pasting code, STOP. Create a reusable
helper, utility, or component instead.

### Keep it Dynamic

Hardcoding values or writing repetitive boilerplate is a fast track to
sadness. Make your code modular and easily adjustable from a single
source of truth.

### Maintainability First

A contributor shouldn't have to wander through half the codebase just to
tweak a single feature or fix a bug in one place. Keep things
centralized.

## No Complete File Overwrites

Do not delete a file's entire contents and paste the modified version
back in. Make precise, line-by-line edits directly so I can review the
exact diff accurately.

## 2-Day Window for Requested Changes

If I request updates or fixes on your PR, you have a maximum of 2 days
to implement them. Taking longer indicates that the proposed code is
fundamentally broken or unviable.

## 2-Day Deadline for Assigned Issues

If an issue is assigned to you, you have a maximum of 2 days to complete
the requested work and submit a Pull Request (PR). Make sure your PR is
ready for review within this timeframe.

## Responsive Communication

Please reply to any questions or review comments within 12-24 hours.

## Keep it Simple & Readable (No Over-Engineering)

If you are solving a problem, write the simplest possible code to
achieve it (simple code, not just a simple fix). Avoid
over-engineering---keep your implementation simple, clean, and highly
readable.
